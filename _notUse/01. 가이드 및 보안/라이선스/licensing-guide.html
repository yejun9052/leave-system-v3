라이선스 발급 가이드

고객사마다 라이선스를 발급(서명)해 전달하는 방법입니다. 발급은 비공개 키로만 가능하고, 앱에는 공개 키만 들어 있어 고객은 위조할 수 없습니다.

🔑

핵심 — 라이선스는 항상 집행됩니다. 유효한 키가 없으면 고객 서버에서 로그인 포함 모든 기능이 차단됩니다. 그래서 배포 시 고객마다 라이선스 발급·전달이 필요합니다.

STEP 1

준비 (최초 1회 · 코드 변경 후)

발급 도구를 컴파일합니다. 키 쌍은 이미 만들어져 있습니다 — 공개키는 앱에 내장, 비공개키는 LICENSE-PRIVATE-KEY.txt에 보관.

PowerShell$env:JAVA_HOME='C:\Program Files\Eclipse Adoptium\jdk-21.0.11.10-hotspot'
cd C:\alwork
.\gradlew.bat :backend:compileJava
STEP 2

라이선스 발급 (고객마다)

인자: 비공개키 · 회사명 · 만료일 · 최대인원 · host 순서.

PowerShell · 예) 가나상사 · 2027-12-31 · 50명 · leave.gana.co.krjava -cp backend\build\classes\java\main com.company.leave.license.tool.LicenseTool `
     issue "<비공개키>" "가나상사" 2027-12-31 50 leave.gana.co.kr

# 출력 →
=== LICENSE (고객 서버 LICENSE_KEY 로 설정) ===
eyJpZCI6...(긴 문자열)...RAiCQ
순서인자예
1비공개 키 (Base64)LICENSE-PRIVATE-KEY.txt의 값
2회사명"가나상사" (공백 시 따옴표)
3만료일2027-12-31
4최대 사용자수50 (0=무제한)
5설치처 hostleave.gana.co.kr

출력된 라이선스 문자열을 고객에게 전달합니다. (문자열 자체는 비밀이 아니며 위조 불가 — 비밀은 오직 비공개 키입니다.)

STEP 3

고객 적용 (전달 시 안내)

고객 서버 .env에 발급 문자열과 host를 넣고 재기동합니다.

고객 서버 · .envLICENSE_KEY=<발급한 라이선스 문자열>
LICENSE_HOST=leave.gana.co.kr   # 발급 때 host 와 동일
고객 서버docker compose -f docker-compose.prod.yml up -d

적용 확인: 정상 로그인되면 완료. GET /api/license로 상태 조회 가능. 만료 30일 전부터 상단 갱신 배너가 뜹니다.

갱신

연장 · 변경 · 정지

상황방법
기간 연장새 만료일로 재발급 → 고객 LICENSE_KEY 교체 후 재기동 (host 동일)
인원 변경새 maxUsers로 재발급 → 동일하게 교체
정지갱신하지 않으면 만료일에 자동 차단
보안

비공개 키 관리

⚠️

비공개 키는 절대 노출 금지

유출되면 누구나 유효한 라이선스를 위조할 수 있습니다.

  • 서버·저장소·고객 어디에도 두지 말 것 — 공급사 내부 암호관리자/오프라인 보관
  • 분실 시: 새 키 쌍 생성 + 공개키 교체 + 앱 재배포 필요 → 기존 라이선스 전부 무효
FIX

고객 문제 해결

증상원인조치
모든 기능 차단키 미설정·만료·위조LICENSE_KEY 확인, 만료면 재발급
설치처(host) 불일치LICENSE_HOST ≠ 발급 host값 일치 또는 올바른 host로 재발급
사용자 추가 시 상한 도달maxUsers 초과인원 상향해 재발급

한눈에 보기

  1. 준비 — gradlew :backend:compileJava (최초 1회)
  2. 발급 — LicenseTool issue "비공개키" "회사명" 만료일 최대인원 host
  3. 전달 — 출력 문자열 → 고객 .env의 LICENSE_KEY + LICENSE_HOST → 재기동
  4. 주의 — 비공개 키(LICENSE-PRIVATE-KEY.txt)는 안전하게 보관
