Annual Leave Management System · 운영 매뉴얼

연차관리 시스템 모듈 문서

근로기준법 기반 연차·반차 관리 시스템. 웹/모바일(반응형·PWA)에서 동작하며, 단일 실행 파일(app.jar)에 UI·API·라이선스가 번들되어 Docker로 배포됩니다.

Java 21 Spring Boot 3.4 PostgreSQL 16 React 18 · Vite 배포 Docker Compose 보안 JWT · 난독화 · 라이선스

개요

회사에서 실제 운영 가능한 상용 수준의 연차/반차 관리 시스템입니다. 연차 자동 부여·소멸, 부서/사용자 관리, 권한 분리(RBAC), 결재 워크플로우, 전사 캘린더, 대시보드/리포트를 제공합니다.

아키텍처

3개의 컨테이너로 동작합니다. 서버에는 Docker만 있으면 되고, 자바(JRE)·프론트엔드는 app.jar에, DB는 컨테이너에 포함됩니다.

설정 개요

설정은 세 곳으로 나뉩니다: 접속·비민감 설정은 .env, 민감 비밀은 secrets/ 파일, 라이선스는 .env(키 문자열)입니다.

항목위치비고
접속 주소·DB명·라이선스.env평문(민감정보 아님)
DB 비밀번호 · JWT 서명키secrets/db_password, secrets/jwt_secretDocker secret(선택 암호화)
접속 포트docker-compose.prod.yml기본 80/443, 변경 가능

1) 접속 설정 — .env

cp .env.prod.example .env 후 편집. 두 모드 중 하나를 선택합니다.

모드 A · 도메인+HTTPS (권장)모드 B · IP+HTTP (임시)
SITE_ADDRESSleave.회사.com:80 (또는 지정포트는 :80 유지)
APP_ORIGINhttps://leave.회사.comhttp://서버IP[:포트]
준비물도메인 + DNS A레코드없음
암호화(HTTPS)O (자동 발급)X (사내/테스트)
 
# .env 예시 (모드 A)
SITE_ADDRESS=leave.회사.com
APP_ORIGIN=https://leave.회사.com
POSTGRES_DB=annual_leave
POSTGRES_USER=leave
LICENSE_KEY=eyJpZCI6...(발급받은 문자열)...
LICENSE_HOST=leave.회사.com
# DB 비밀번호·JWT 는 .env 에 두지 않음 → secrets/ 파일 (아래 2)

2) 비밀정보 — secrets/ (Docker secrets)

DB 비밀번호·JWT 서명키는 파일로 관리되어 컨테이너 내부 /run/secrets/ 로만 주입됩니다(환경변수·docker inspect에 노출되지 않음). install.sh 사용 시 자동 생성됩니다.

# 수동 생성 (줄바꿈 없이)
mkdir -p secrets
printf '%s' "$(openssl rand -base64 24 | tr -dc 'A-Za-z0-9' | cut -c1-28)" > secrets/db_password
printf '%s' "$(openssl rand -base64 48 | tr -dc 'A-Za-z0-9' | cut -c1-64)" > secrets/jwt_secret
chmod 700 secrets && chmod 600 secrets/*

(선택) 시크릿 파일 암호화

암호문으로 보관하려면 마스터키(앱 폴더 밖 root 전용)로 암호화합니다. 기동 시 자동 복호화됩니다.

bash secrets-encrypt.sh   # master.key + secrets.enc/*.enc 생성
rm -f secrets/*          # 평문 제거(배포 때 복호화)
마스터키(master.key)는 반드시 별도 백업하세요. 분실 시 복호화가 불가능합니다.

3) 포트 변경

80번이 다른 서비스와 겹치면 web 포트를 바꿉니다. (SITE_ADDRESS는 컨테이너 내부 포트라 :80 유지)

# docker-compose.prod.yml
  web:
    ports:
      - "8090:80"     # 호스트 8090 → 컨테이너 80
# .env
APP_ORIGIN=http://서버IP:8090

4) 라이선스

라이선스는 항상 집행됩니다. 유효한 키가 없으면 로그인 포함 모든 기능이 차단됩니다.

  • LICENSE_KEY: 공급사가 발급한 서명 문자열
  • LICENSE_HOST: 발급 시 지정한 host와 정확히 일치해야 함(회사명 아님)
  • 만료·최대 사용자수·설치처(host) 검증. 만료 30일 전부터 상단 배너 표시. 상태는 GET /api/license

5) 프로파일 & 초기 관리자 비밀번호

  • 기본 활성 프로파일은 prod (env 없이 실행해도 개발용 시크릿으로 폴백되지 않음).
  • 로컬 개발은 gradlew bootRun(자동 local) 또는 --spring.profiles.active=local.
  • 운영 초기 관리자 비밀번호는 설치마다 무작위 생성되어 최초 기동 로그에 1회 표시(고정 기본값 없음). → 설치 탭 참고.

3.1 설치에 필요한 툴

운영 서버에는 Docker 하나면 됩니다. 개발 PC의 도구는 소스 수정 후 app.jar를 다시 빌드할 때만 필요합니다.

대상툴용도필수?
운영 서버Docker + compose 플러그인컨테이너 실행필수
개발 PCJDK 21 (Temurin)백엔드 빌드빌드 시
개발 PCNode.js 20+프론트 빌드(jar 번들)빌드 시

운영 서버 — Docker 설치

Ubuntu / Debian# 공식 편의 스크립트
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER   # 재로그인 후 적용
CentOS / RHEL / Rocky / Almasudo dnf install -y dnf-plugins-core
sudo dnf config-manager --add-repo https://download.docker.com/linux/centos/docker-ce.repo
sudo dnf install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
sudo systemctl enable --now docker
더 간편하게: 배포 패키지의 install.sh 가 OS 선택 메뉴로 Docker 설치부터 기동까지 자동 처리합니다(아래 3.2).

개발 PC — 빌드 도구 (Windows)

winget install EclipseAdoptium.Temurin.21.JDK
winget install OpenJS.NodeJS.LTS

3.2 설치 절차

방법 A — install.sh 자동 (권장)

내 PC → 서버 업로드scp install.sh annual-leave-deploy.tar.gz 사용자@서버IP:~/
서버sudo bash install.sh        # OS 선택 → Docker 설치 → 압축해제 → 시크릿 생성
# 안내에 따라 .env 편집(접속주소·라이선스) 후 기동

방법 B — 수동

  1. 압축 해제

    tar xzf annual-leave-deploy.tar.gz && cd annual-leave

  2. 환경설정

    cp .env.prod.example .env && nano .env   # 접속주소·DB명·라이선스

  3. 시크릿 생성 (DB 비번·JWT)

    mkdir -p secrets
printf '%s' "$(openssl rand -base64 24 | tr -dc 'A-Za-z0-9' | cut -c1-28)" > secrets/db_password
printf '%s' "$(openssl rand -base64 48 | tr -dc 'A-Za-z0-9' | cut -c1-64)" > secrets/jwt_secret
chmod 700 secrets && chmod 600 secrets/*

  4. 기동

    docker compose -f docker-compose.prod.yml up -d --build
docker compose -f docker-compose.prod.yml ps   # 3개 Up 이면 성공

3.3 최초 로그인

초기 관리자 비밀번호는 최초 기동 로그에 1회만 표시됩니다(설치마다 무작위).

docker compose -f docker-compose.prod.yml logs backend | grep -A4 "초기 관리자 계정 생성"
# 이메일: admin@company.com / 초기 비밀번호: (로그의 값)
로그인 후 즉시 비밀번호를 변경하세요. 관리자 계정은 사용자 목록에 노출되지 않으며, 우상단 [내 정보 → 비밀번호 변경] 으로 변경합니다.

운영 명령

# 상태 / 로그
docker compose -f docker-compose.prod.yml ps
docker compose -f docker-compose.prod.yml logs -f backend
# 중지 / 시작 / 재시작
docker compose -f docker-compose.prod.yml stop
docker compose -f docker-compose.prod.yml restart web

데이터 백업 / 복구

# 백업 (매일 cron 권장)
docker exec leave-postgres pg_dump -U leave annual_leave | gzip > leave_$(date +%F).sql.gz
# 복구
gunzip -c leave_YYYY-MM-DD.sql.gz | docker exec -i leave-postgres psql -U leave -d annual_leave
DB는 도커 볼륨 pgdata, 인증서는 caddy_data 에 영구 저장됩니다.

소스 수정 후 재배포 (개발 PC)

프론트+백엔드를 한 번에 빌드해 난독화 app.jar 로 만든 뒤, 소스 없는 패키지로 배포합니다.

내 PC (실제 경로에서).\gradlew.bat :backend:bootJarObf
copy backend\build\libs\backend-obf.jar backend\app.jar
.\scripts\package-deploy.ps1        # 소스 미포함 패키지 생성(자동 검증)
서버tar xzf annual-leave-deploy.tar.gz && cd annual-leave
docker compose -f docker-compose.prod.yml up -d --build   # Flyway 자동 마이그레이션
서버의 .env·secrets/ 는 패키지에 없어 그대로 유지됩니다. 데이터도 보존됩니다.

보안 체크리스트 (배포 전)

  • 초기 관리자 비밀번호 변경(로그 확인 후)
  • DB 비번·JWT는 secrets/ 파일(무작위·강력), chmod 600
  • .env·secrets/ git·백업 공유 제외
  • 방화벽 22/80/443만 개방(5432·8080 외부 차단)

  • SSH 키 로그인만 허용, 디스크/볼륨 암호화(권장)
