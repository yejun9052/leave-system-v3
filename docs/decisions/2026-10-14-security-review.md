## 참고 (보안 문제는 아님)

- CSRF 쿠키가 세션에 묶이지 않음 → 같은 상위 도메인의 다른 서브도메인이 뚫리면 우회 가능(서브도메인에 배치할 때만, 추정)
- 아무 팀장이나 임의 휴가 id의 결재 대기 여부를 알 수 있음(권한보다 상태를 먼저 확인)
- 팀장이 API로 `PERSONAL` 일정을 만들면 본인도 못 봄. 권한이 바뀐 뒤에도 자기가 만든 일정은 지울 수 있음
- 연속 사용 한도를 바로 붙은 묶음으로 나눠 피할 수 있음 → 회사 확인 중인 [연속 사용 한도] 질문과 같은 문제

## 문제없음으로 확인한 것

- **권한**
  - `@PreAuthorize` 누락 없음
  - 묶음 API는 대리 신청 불가, 강제 등록은 인사관리자만
  - 결재 권한(맡은 부서·하위, 최상위 부서장 자가 승인)과 부서장 지정 경로(`DepartmentLeadSync`만)
  - 스스로 권한 올리기·퇴사 불가, admin 계정 보호
  - 팀장 조회 범위, 일반 직원에게 이메일·전화 비공개
- **묶음 기능**
  - 31묶음 상한(서버), 겹침 거부, 전부 성공 또는 전부 취소, 잔액 이중 계산 없음, 미리보기와 신청이 같은 `plan()`
- **동시성**
  - `@Version`으로 이중 승인·승인 중 취소가 충돌로 끝남
  - 승인 시 잔액·겹침 재확인
- **인증**
  - 세션 고정 방지, 계정 존재 노출 없음, 재설정 토큰(32바이트·해시·1회용), 임시 비밀번호(SecureRandom 12자)
  - 로그아웃·퇴사·재설정 시 모든 세션 삭제
- **헤더·쿠키**
  - CSRF 예외 경로 없음, 쿠키 HttpOnly·Secure·SameSite=Lax, CORS 한 주소만
  - CSP·HSTS 등 보안 헤더
  - 경로 변형(대소문자, `;`, `//`, `/../`, `%2e`, `%2f`)은 방화벽이 막음
- **화면**
  - `dangerouslySetInnerHTML` 등 없음, 색 값 검사, 메일 HTML 이스케이프
  - 브라우저 저장소에 비밀번호·토큰 없음, 권한 없는 화면은 데이터가 보이기 전에 이동
- **파일**
