## 1. 부서·사용자 선택 출력

| 항목 | 결정 |
|---|---|
| 기본 동작 | 아무것도 고르지 않으면 지금처럼 전체를 출력한다 |
| 부서 선택 | **부서 트리 체크박스.** 상위 부서를 체크하면 하위 부서가 자동으로 체크되고, 하위 부서는 하나씩 해제할 수 있다 |
| 사용자 선택 | 목록에서 체크한다(연차 촉진 대상 목록과 같은 방식). 검색할 수 있다 |
| 대상 | 체크된 부서의 소속 직원 **합** 체크된 사용자. 서버는 화면에서 체크된 부서 id를 그대로 받는다(하위 부서를 서버에서 따로 펼치지 않음) |
| 양식·정렬 | 바꾸지 않는다(연구소 연차현황표, 부서 트리 순서 → 부서 안은 입사일 순) |
| API | `GET /api/reports/leave-usage/export?year=&departmentIds=&employeeIds=` |

**같은 부서 트리 선택을 다른 화면에도 적용한다** (리포트 다음 단계, 같은 부품 재사용)
- 사용자 관리(직원 목록 검색)
- 휴가 목록(휴가 현황·결재 목록 검색)
- 연차 촉진 대상(정책 › 촉진·미사용 탭)

## 2. 경조사 사용 내역

| 항목 | 결정 |
|---|---|
| 위치 | 연차 현황표 아래에 3줄을 띄우고 "경조사 사용 내역" 표를 둔다. 정해진 양식은 없다 |
| 열 | 이름 / 부서 / 경조사 규정 / 사용일 / 일수 |
| 대상 | 리포트 연도에 시작한, **승인된** 경조사 규정 휴가. 생일 반차를 포함한다 |
| 선택 | 1번의 부서·사용자 선택을 똑같이 적용한다 |

## 3. 엑셀 내보내기 감사 로그

| 항목 | 결정 |
|---|---|
| 대상 | 리포트 내보내기 `GET /api/reports/leave-usage/export`, 사용자 엑셀 내보내기 `GET /api/employees/export` |
| 기록 | 누가, 언제, 어떤 조건(연도, 선택한 부서·사용자)으로 내려받았는지 |
| 방법 | `AuditAspect`가 "GET이면서 `/export`로 끝나는 요청"도 기록한다. 조건은 요청 주소의 조회 조건을 그대로 남긴다. `EmployeeController`는 고치지 않는다 |
